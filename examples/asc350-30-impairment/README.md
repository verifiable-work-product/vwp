# Example: ASC 350-30 impairment of NFT lots (synthetic)

A demo VWP package testing fictional NFT lots (outside ASC 350-60) for impairment under ASC 350-30-35: per lot, carrying amount against observed fair value, the loss, the new carrying amount, and a later retest that starts where the first one left off.

**All data is synthetic. This example is not accounting, legal or tax advice.**

What it demonstrates:

- `indefiniteLivedIntangibleImpairmentTest` calculations recomputed lot by lot (`asc35030.impairment.recompute`), with no reversal (`asc35030.impairment.noReversal`) and continuity across tests (`asc35030.impairment.continuity`).
- Fair values that must equal the pricing facts they cite (`asc35030.impairment.fairValueEvidence`).
- The required `impairment` accounting schedule, one loss entry per impaired lot on its test date.

Generated by the Go SDK's fixture generator (`cd sdk/go && go run fixturegen/main.go`),
which refuses to write a package that does not verify clean; object ids carry the
section prefixes (`s1_` … `s5_`) of the authoring template.
