# Extension Sketch: `vwp-accounting-asc350-30` (Indefinite-Lived Intangible Impairment)

> **Status:** Experimental draft (v0.1). This is not accounting advice. All example
> data is synthetic. VWP validation is not an audit opinion, legal opinion, accounting
> opinion, or assurance engagement.

How an impairment memo for digital assets *outside* ASC 350-60 (NFTs, tokens that
fail a scope criterion) maps onto VWP objects: the indefinite-lived intangible
impairment test of ASC 350-30-35, applied lot by lot.

## Shape of an impairment package

- **Facts** — each lot's carrying amount and the fair value observed on the test date,
  with pricing evidence.
- **Judgments** — the triggering event, the unit of account, and the fair value
  conclusion where inputs are unobservable.
- **Calculations** — one impairment test per test date and scope, of type
  `indefiniteLivedIntangibleImpairmentTest`
  ([`impairment-test.schema.json`](../../schemas/v0.1/extensions/accounting-asc350-30/impairment-test.schema.json)):
  per lot, carrying amount, fair value, loss and new carrying amount.
- **Claims** — recoverability, measurement of the loss, no subsequent reversal.

## Validators (Go SDK)

| Id | Semantics |
|---|---|
| `asc35030.impairment.schemaValid` | Every impairment test validates against the extension schema. |
| `asc35030.impairment.recompute` | Per lot, loss = max(0, carrying − fair value); no lot is tested twice in one test and no output row is duplicated. |
| `asc35030.impairment.noReversal` | The new carrying amount never exceeds the old one (ASC 350-30-35-20 forbids reversal). |
| `asc35030.impairment.fairValueEvidence` | Each lot's fair value equals the value of the fact it cites. |
| `asc35030.impairment.continuity` | A lot tested again later starts from the carrying amount the earlier test left it at. |
| `asc35030.accountingSchedule.tieOut` | The executable schedule books one impairment loss per impaired lot on its test date. |

## Executable accounting schedule

Packages under this extension are required to carry the executable accounting
schedule at `calculations/accounting-schedule.json` whenever the calculations book
anything (see [`accounting-schedule.md`](../accounting/accounting-schedule.md) for
the artifact contract and `core.requiredOutputs.exist`). The schedule's `kind`,
posting roles and amounts are tied out, entry by entry, to the extension's own
calculations by the `asc35030.accountingSchedule.tieOut` validator.

See [`examples/asc350-30-impairment`](../../examples/asc350-30-impairment).
