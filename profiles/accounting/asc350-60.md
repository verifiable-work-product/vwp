# Extension Sketch: `vwp-accounting-asc350-60` (Crypto Assets)

> **Status:** Experimental draft (v0.1). This is not accounting advice. All example
> data is synthetic. VWP validation is not an audit opinion, legal opinion, accounting
> opinion, or assurance engagement.

How an ASC 350-60 crypto asset memo (fair value measurement of in-scope crypto
assets, with the ASC 350-60-50 disclosures) maps onto VWP objects.

## Shape of a crypto asset package

- **Facts** — each asset held and, per asset, the six scope criteria of ASC 350-60-15-1
  (intangible asset, no enforceable rights to underlying goods or services, created or
  resides on a distributed ledger, secured through cryptography, fungible, not created
  or issued by the reporting entity or its related parties).
- **Judgments** — scope conclusions for assets that fail a criterion (wrapped tokens,
  NFTs, issued tokens) and the accounting they route to instead.
- **Calculations** — the per-asset roll-forward (opening, additions, dispositions,
  remeasurement gain/loss, closing; ASC 350-60-50-3) and the significant-holdings
  table (ASC 350-60-50-1: units, cost basis, fair value for each significant holding
  plus "other").
- **Claims** — scope, measurement at fair value, presentation and disclosure.

## Data contracts

- `facts/crypto-assets.json` — the **scope register**, one entry per asset with the six
  criteria, `inScope`, and `outOfScopeTreatment` where applicable
  ([`crypto-assets.schema.json`](../../schemas/v0.1/extensions/accounting-asc350-60/crypto-assets.schema.json)).
- Calculations of type `cryptoAssetRollForward`
  ([`crypto-asset-roll-forward.schema.json`](../../schemas/v0.1/extensions/accounting-asc350-60/crypto-asset-roll-forward.schema.json))
  and `significantCryptoHoldings`
  ([`significant-holdings.schema.json`](../../schemas/v0.1/extensions/accounting-asc350-60/significant-holdings.schema.json)),
  located by `type` so a template's section prefix never hides them.

## Validators (Go SDK)

| Id | Semantics |
|---|---|
| `asc35060.scope.registerPresent` | Fails when `facts/crypto-assets.json` is missing or contains no assets. |
| `asc35060.scope.schemaValid` | The scope register validates against the extension schema. |
| `asc35060.scope.consistent` | `inScope` agrees with the six criteria for every asset; out-of-scope assets name their treatment. |
| `asc35060.scope.judgmentLinked` | Every out-of-scope asset links a resolvable scope judgment. |
| `asc35060.rollForward.schemaValid` | Every `cryptoAssetRollForward` calculation validates against the extension schema. |
| `asc35060.rollForward.tieOut` | Each line and the totals tie; roll-forwards chain by scope and period. |
| `asc35060.rollForward.assetsInScope` | Only in-scope assets appear in a roll-forward. |
| `asc35060.significantHoldings.schemaValid` | Every `significantCryptoHoldings` calculation validates against the extension schema. |
| `asc35060.significantHoldings.tieOut` | Significant and "other" fair value and cost basis recompute from the holdings. |
| `asc35060.significantHoldings.assetsInScope` | Only in-scope assets appear in a holdings table. |
| `asc35060.significantHoldings.tiesToRollForward` | Per asset, the holdings fair value equals the roll-forward's closing balance on that date. |
| `asc35060.accountingSchedule.tieOut` | The executable schedule books each period's remeasurement gain or loss, per asset, in the right direction. |

## Executable accounting schedule

Packages under this extension are required to carry the executable accounting
schedule at `calculations/accounting-schedule.json` whenever the calculations book
anything (see [`accounting-schedule.md`](../accounting/accounting-schedule.md) for
the artifact contract and `core.requiredOutputs.exist`). The schedule's `kind`,
posting roles and amounts are tied out, entry by entry, to the extension's own
calculations by the `asc35060.accountingSchedule.tieOut` validator.

See [`examples/asc350-60-crypto-assets`](../../examples/asc350-60-crypto-assets).
