# Extension Sketch: `vwp-accounting-asc820` (Fair Value Measurement)

> **Status:** Experimental stub (v0.1). This is not accounting advice. All example
> data is synthetic. VWP validation is not an audit opinion, legal opinion, accounting
> opinion, or assurance engagement.

A sketch of how fair value measurement support maps onto VWP objects.

## Shape of a fair value package

- **Claims**
  - The asset (or liability) is measured at fair value of X as of the measurement date.
  - The measurement is categorized in the stated fair value hierarchy level.
  - The principal (or most advantageous) market is as identified.
- **Judgments**
  - **Fair value hierarchy level (Level 1 / 2 / 3)** — modeled as an explicit judgment
    with basis (observability of inputs, market activity) and alternatives considered.
    Level 2 and Level 3 categorizations typically warrant `reviewRequired`.
  - Principal market determination; valuation technique selection for Level 2/3.
- **Evidence**
  - **Pricing source evidence**: exchange price extracts, broker quotes, pricing vendor
    files, order book snapshots — with source system, retrieval time, and hash.
  - Market activity support (volumes, quote depth) for level categorization.
- **Calculations**
  - **Valuation tie-outs**: quantity times price equals reported fair value; portfolio
    totals tie to ledger balances; recomputable with declared rounding tolerance.

## Data contract and demo validators (implemented in the reference CLI)

Packages declaring `vwp-accounting-asc820` carry a **fair value measurement
register** at `facts/fair-value-measurements.json`, validating against
[`schemas/v0.1/extensions/accounting-asc820/fair-value-measurements.schema.json`](../../schemas/v0.1/extensions/accounting-asc820/fair-value-measurements.schema.json):
one entry per measurement with asset, measurement date, hierarchy `level`
(`level1`/`level2`/`level3`), valuation technique, fair value, pricing source
evidence references, unobservable inputs, and (for level 3) a judgment reference.

The reference CLI implements:

- **`asc820.measurements.schemaValid`** — the register conforms to the extension schema.
- **`asc820.pricingSources.resolve`** — every measurement's pricing source references
  resolve to evidence in the package.
- **`asc820.level3.judgmentLinked`** — every level 3 measurement links a resolvable
  judgment covering hierarchy classification and unobservable inputs, because leveling
  is professional judgment, not arithmetic.

See [`examples/asc820-fair-value`](../../examples/asc820-fair-value) for a synthetic
example package (a level 1 ETH position and a level 3 restricted token with a
documented discount for lack of marketability). Valuation tie-out validators
(quantity × price recomputation with declared rounding tolerance) remain roadmap
items.
